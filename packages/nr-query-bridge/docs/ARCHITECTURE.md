# Architecture

## Pipeline

```
SPL string → Peggy parser → AST → splToIR → IR → optimize → irToNrql → NRQL string
```

| Stage | What it does | Entry point |
|---|---|---|
| **Parse** | SPL text → AST (syntax tree of commands, expressions, values) | `splParser.js` (generated by Peggy from `spl.grammar`) |
| **Translate** | AST → IR (language-neutral query plan: SelectQuery with select/where/facet/etc.) | `splToIR.js` → handler files |
| **Optimize** | IR → IR (simplify: fold constants, eliminate double-NOT, expand DualCheck, apply fillnull/replace) | `ir/optimize.js` |
| **Emit** | IR → NRQL string (escape identifiers, handle precedence, format clauses) | `irToNrql.js` |

Top-level entry: `translate.js` — calls parse → translate → optimize → emit.

## File Map

### IR (`src/ir/`)
- `nodes.js` — IR node constructors (Identifier, Literal, BinOp, Func, SelectQuery, DualCheck, etc.)
- `transform.js` — `transformTree(node, fn)` — generic bottom-up tree walker
- `optimize.js` — optimization pass pipeline (6 passes composed via reduce)

### SPL Input (`src/input/spl/`)
- `spl.grammar` — Peggy grammar definition for SPL
- `splParser.js` — generated parser (do not edit)
- `splToIR.js` — entry point + search expression translation + command dispatch table
- `splExprUtils.js` — shared utilities: field mapping, function mapping, comparison builders, arithmetic parsing
- `evalHandlers.js` — eval/where command handlers + the recursive eval expression walker (~600 lines)
- `aggregationHandlers.js` — stats, timechart, top, rare, eventstats
- `enrichmentHandlers.js` — join, append, appendpipe, lookup, inputlookup
- `extractionHandlers.js` — rex, spath, regex, search pipe
- `rowHandlers.js` — fields, sort, head, rename, dedup, bin, fillnull, convert, replace, strcat
- `splTime.js` — SPL time expression parsing (earliest, latest, relative times)

### NRQL Output (`src/output/nrql/`)
- `irToNrql.js` — IR → NRQL string emitter
- `nrqlEncoding.js` — identifier escaping, string literal escaping

## Worked Example

Input SPL:
```spl
index=web status=500 | eval duration_sec = duration / 1000 | stats avg(duration_sec) by host | sort -avg_duration_sec | head 10
```

### Stage 1: Parse → AST

The Peggy parser produces:
```js
{
  search: {
    type: 'BooleanOp', operator: 'AND',
    left:  { type: 'Comparison', field: 'index', operator: '=', value: 'web' },
    right: { type: 'Comparison', field: 'status', operator: '=', value: '500' },
  },
  commands: [
    { type: 'EvalCommand', assignments: [{ field: 'duration_sec', expr: /* arithmetic */ }] },
    { type: 'StatsCommand', functions: [{ name: 'avg', args: ['duration_sec'] }], groupBy: ['host'] },
    { type: 'SortCommand', fields: [{ field: 'avg_duration_sec', direction: 'desc' }] },
    { type: 'HeadCommand', count: 10 },
  ]
}
```

### Stage 2: Translate → IR

`translateAstToIR` processes the search clause into WHERE, then each command transforms the IR:

```js
SelectQuery({
  dataSource: EventType(['Log']),
  where: BinOp('AND',
    BinOp('=', Identifier('index'), Literal('web', 'string')),
    DualCheck(Identifier('status'), '=', Literal(500, 'number')),
  ),
  bindings: [Binding('duration_sec', BinOp('/', Func('numeric', [Identifier('duration')]), Literal(1000, 'number')))],
  select: [Func('average', [Identifier('duration_sec')])],
  facet: [Identifier('host')],
  orderBy: OrderBy(Identifier('avg_duration_sec'), true),
  limit: 10,
})
```

### Stage 3: Optimize → IR

The optimization pipeline runs 6 passes. For this query:
- `expandDualChecks` expands `DualCheck(status, =, 500)` → `status = '500' OR numeric(status) = 500`
- Other passes are no-ops (no double-NOT, no constant folding opportunities, no fillnull/replace maps)

### Stage 4: Emit → NRQL

`irToNrql.js` walks the IR and produces:
```sql
FROM Log WITH numeric(duration) / 1000 AS duration_sec
SELECT average(duration_sec)
WHERE index = 'web' AND status = '500' OR numeric(status) = 500
FACET host ORDER BY avg_duration_sec DESC LIMIT 10
```

## Command Dispatch

`splToIR.js` uses a dispatch table to route commands to handler files:

```js
const handlers = {
  StatsCommand:      handleStats,       // aggregationHandlers.js
  TimechartCommand:  handleTimechart,    // aggregationHandlers.js
  JoinCommand:       handleJoin,         // enrichmentHandlers.js
  RexCommand:        handleRex,          // extractionHandlers.js
  EvalCommand:       handleEval,         // evalHandlers.js
  FieldsCommand:     handleFields,       // rowHandlers.js
  // ... 30+ commands total
};
```

Commands too small for their own handler (predict, tstats, macro) stay inline in the fallback switch.
