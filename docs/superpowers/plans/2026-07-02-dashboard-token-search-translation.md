**Goal:** Translate Splunk dashboard `$token$` in comparison-field position and bare-term
position to faithful NRQL, and fail loud on the one shape that can't be expressed.

**Architecture:** All changes are in the SPL→IR stage (`splToIR.js`) plus the message catalog;
the grammar already emits the needed nodes (`Comparison{lhsToken}`, bare `TemplateVariable`).
The work supersedes the unmerged flip (#91): Task 1 reverts it to the clean floor, then Tasks
2–5 stack the real translations on top.

**Tech Stack:** Pure ESM JS; Peggy parser (no grammar change expected); Vitest data-driven
`cases` in `test/spl/spl.test.js`; git-town stacked PRs.

### Task 2: Field-selector passthrough — `$tok$ <op> <value>` → `{{tok}} <op> <value>`

Branch: `feat/token-lhs-passthrough`, stacked on `feat/token-in-lhs-flip`. Translate a token in
field position by emitting it as the identifier and passing the operator through. The RHS is a
string literal, or — for a *different* token in value position — another `{{…}}` (so
`$cat$ = $other$` → `{{cat}} = {{other}}`, different variables, no conflict). The exact-`"*"`
wildcard is deferred to Task 3; here it stays at the floor.

**Files:**
- Modify: `src/input/spl/splToIR.js` (the `if (node.lhsToken)` branch; the `Identifier`,
  `Literal`, `BinOp` factories are already imported — confirm at the top of the file)
- Modify: `test/spl/spl.test.js`

**Interfaces:**

- Produces: `if (node.lhsToken)` returns `BinOp(op, Identifier('{{tok}}'), <rhs>)` for non-`*`
  values, where `<rhs>` is `Identifier('{{other}}')` for a token RHS else `Literal(value,
  'string')`. `value === '*'` still floors (Task 3 upgrades it).

- [ ] **Step 3: Run — expect fail** (still floored).

Run: `ASDF_NODEJS_VERSION=24.14.0 npm run test --workspace=@newrelic/query-bridge -- spl.test`

- [ ] **Step 4: Implement the passthrough.** Replace the Task-1 `if (node.lhsToken)` floor block with:

```js
if (node.lhsToken) {
  const tok = node.lhsToken.name;
  const { operator, value } = node;
  // `="*"` is field-existence — handled in Task 3; until then, floor it.
  if (value === '*') {
    ir.unsupported.push(messages.token_lhs_unsupported(tok));
    return null;
  }
  // RHS: a different token → {{other}} (base RHS is a TemplateVariable node; where RHS is a
  // raw `$other$` string). Otherwise a string literal.
  let rhs;
  if (value && typeof value === 'object' && value.type === 'TemplateVariable') {
    rhs = Identifier(`{{${value.name}}}`);
  } else if (typeof value === 'string' && /^\$[A-Za-z0-9_.:-]+\$$/.test(value)) {
    rhs = Identifier(`{{${value.replace(/^\$|\$$/g, '')}}}`);
  } else {
    rhs = Literal(value, 'string');
  }
  return BinOp(operator, Identifier(`{{${tok}}}`), rhs);
}
```

### Task 4: Same-token conflict guard → `token_strategy_conflict`

Branch: `feat/token-lhs-conflict-guard`, stacked on `feat/token-lhs-existence`. The broad
invariant: if the **same** token appears in both field position (a `lhsToken`) and value
position (a `{{name}}` emitted from a token) in one query, no single `replacementStrategy`
satisfies both — loud unsupported. This is what catches the OR idiom `($cat$="*" OR
category="$cat$")` (which would otherwise emit `{{cat}} IS NOT NULL OR category = {{cat}}`).

**Files:**
- Modify: `src/messages.js` (add `token_strategy_conflict`)
- Modify: `src/input/spl/splToIR.js` (track field-position vs value-position token names; guard
  after the pipeline loop, beside the existing post-loop warning emission)
- Modify: `test/spl/spl.test.js`

**Interfaces:**
- Consumes: the lhsToken branch (Tasks 2–3) and every value-position `{{name}}` emit site.
- Produces: two `Set`s on `ir` — `_tokenFieldPos`, `_tokenValuePos` — and a post-loop check that
  pushes `token_strategy_conflict(name)` for any name in both.

- [ ] **Step 1: Add the message.** In `src/messages.js`, beside the other token messages:

```js
// SPL: `($tok$="*" OR field="$tok$")` — same token used as a field AND a value in one query.

  `the dashboard variable $${token}$ is used in both field position and value position in the ` +
  'same query; New Relic gives a variable one replacement strategy (a field needs IDENTIFIER, ' +
  'a value needs a quoted string), so the two uses cannot coexist — this query cannot be translated.',
```
