# `append` Divergent Time-Window Guard — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make `append`/`appendcols` emit a loud `unsupported` when the subsearch carries its own time window that differs from the main query's, instead of silently dropping the subsearch window and running both sides over the main window.

**Architecture:** `handleAppend` already merges `select`/`facet`/`where` but ignores `subIR.since`/`subIR.until`. NRQL has one `SINCE`/`UNTIL` per query, so a "this period vs last period" append (`earliest=-1d … | append [… earliest=-2d latest=-1d …]`) silently returns the main count twice. Add one detection — after the existing cross-source guard, before the WHERE-merge — that compares the subsearch's window to the main's and fails loud when they diverge.

**Source spec:** `docs/superpowers/specs/2026-06-28-append-subsearch-design.md` (Defect 2; this is the spec's PR 2, deferred from the cross-source PR). This is the **only** remaining append defect — Defect 1 (cross-source) shipped on `feat/append-cross-source`.

**Branch strategy (git-town):** create `feat/append-divergent-time` as a git-town branch whose **parent is `feat/append-cross-source`** — it extends that branch's `handleAppend` (the cross-source guard) and its `append_*` message block, so it must build on that baseline. `git config git-town-branch.feat/append-divergent-time.parent feat/append-cross-source` (+ `.branchtype feature`); headless PR via `gh pr create --base feat/append-cross-source`. **If `feat/append-cross-source` has already merged to `master` by build time, parent on `master` instead** (the cross-source changes will be present there). One commit → one PR.

## Engine-Grounded Facts (verified against `feat/append-cross-source` + CLI, 2026-06-30)

- `handleAppend(cmd, ir, label)` (`src/input/spl/enrichmentHandlers.js`) handles both `append` and `appendcols`. Order on the cross-source baseline: parse `subIR` → forward sub warnings/unsupported → **no-agg guard** → **facet-mismatch guard** → **cross-source guard** (`collectSourceDiscriminators(ir.where) !== collectSourceDiscriminators(subIR.where)` → `append_cross_source`) → WHERE-merge (same WHERE → merge selects + `append_merged`; differ → `filter()` wrap + `append_filter_warning`).
- `ir.since`/`ir.until` and `subIR.since`/`subIR.until` hold the parsed window from `earliest=`/`latest=`. They are `null` when unset.
- `exprsEqual(a, b)` already exists in this file (`a === b || (a && b && JSON.stringify(a) === JSON.stringify(b))`) — null-safe deep compare. Reuse it to compare windows.
- **Divergence rule:** divergent iff the subsearch *carries* a window AND it differs from the main's: `subHasWindow = subIR.since != null || subIR.until != null`, then `subHasWindow && (!exprsEqual(subIR.since, ir.since) || !exprsEqual(subIR.until, ir.until))`. A subsearch with **no** window inherits the main's → faithful (not divergent). Same window on both sides → faithful.
- **Today's silent-wrong output** (verified CLI): `earliest=-1d latest=now | stats count | append [search * earliest=-2d latest=-1d | stats count]` → `FROM Log SELECT count(*), count(*) SINCE 1 day ago` + `append_merged` warning (the `-2d..-1d` sub window is dropped).
- **Regressions that must stay faithful** (verified CLI): same-window → `FROM Log SELECT count(*), filter(count(*), WHERE message LIKE '%error%') SINCE 1 day ago` + `append_filter_warning`; different-WHERE → two independent `filter()` counts.

- [ ] **Step 4: Add the guard** in `src/input/spl/enrichmentHandlers.js` `handleAppend`, immediately **after** the cross-source guard (`append_cross_source`) and **before** the "Same WHERE → just merge" block:
```js
  // Defect 2 — divergent per-side time window. handleAppend merges select/facet/where
  // but not since/until, so a subsearch carrying its own earliest/latest is silently
  // dropped and both aggregates run over the main window. NRQL has one SINCE/UNTIL per
  // query, so there is no faithful single-query form when the windows differ.
  const subHasWindow = subIR.since != null || subIR.until != null;
  if (
    subHasWindow &&
    (!exprsEqual(subIR.since, ir.since) || !exprsEqual(subIR.until, ir.until))
  ) {
    ir.unsupported.push(messages.append_divergent_timerange(label));
    return;
  }
```
