# Key Design Decisions

Architectural choices that affect how code should be written and modified.

> **This file is where shipped specs graduate.** When a `docs/superpowers/` spec/plan ships, its durable *invariants* (things a future edit could violate) move here as one-liners; the spec/plan is then deleted (git history is the archive). Before deleting any shipped spec/plan, confirm its invariants are captured below — distill, don't archive. The build narrative (alternatives weighed, corpus counts, "how we got here") dies with the spec; only the load-bearing rule survives. Retiring a spec is a good moment to run `/nr:reflect`. **Graduate only invariants that exist in `src/` today — verify against the code, never transcribe a spec's *proposed* design; treat any existing bullet as suspect until you've confirmed the named functions/fields exist.**

## IR & Optimization
- **DualCheck IR node**: `SPL: status=500` → `DualCheck` node → expanded by optimizer to `status = '500' OR numeric(status) = 500`. Consolidates dual-check logic from 2 call sites into 1 expansion pass.
- **Subquery wrapping (naive)**: post-aggregation `handleStats`/`handleWhere`/`handleEval` call `wrapAsSubquery` to **naively** wrap the current query as a `SubquerySource` — no fold/legality decision in the handler; `foldPostAggregationPass` (below) collapses the over-nesting. Inner takes `dataSource/bindings/select/where/facet/limit/timeseries`; outer keeps `orderBy/limit/since/until/_fieldReplacements`. `timeseries` moves INTO the inner — TIMESERIES belongs to the aggregation that owned it (e.g. a `timechart` before a trailing `stats`); nested TIMESERIES populates all buckets (verified on staging) — and is cleared on the outer. `_time`/`timestamp`/bin-`_time`-alias facet keys are stripped from the inner when timeseries is present (shared `stripTimeBucketFacets`, used by both the wrap and the `splToIR` post-loop). An inner FACET forces inner `LIMIT MAX`.
- **`foldPostAggregationPass` owns collapse + legality** (`src/ir/foldPostAggregation.js`, registered in `optimize.js`'s pass list): the handlers naive-wrap (above), then this pass walks the over-nested `SubquerySource` chain and rewrites it into legal, minimal-subquery NRQL — the transient over-nested IR is never emitted. `foldPostAggregation(ir, warnings, dropped, rootUnsupported)` is the recursive core; `foldPostAggregationPass(ir)` is the registered wrapper that runs the catch-all guards + ensures inner `LIMIT MAX`. This replaced the old `_rowWiseOuter` / `compound_rewrap_unsupported` bail (both removed).
  - **eval folds INTO the aggregation (flat, no subquery)** when every function is fold-safe (`isFoldSafe` / `FOLD_SAFE_FUNCS` = arithmetic + `round abs ceil floor sqrt exp ln log log2 log10 pow mod if case string convert getField extractfield` — the dirac distributed set, verified) **AND** the folded expression references no facet key. `foldEvalLayer` inlines each exposed name to its inner defining expr (transitively — a sibling alias resolves through to the aggregate, not the alias name) and **strips `numeric()` around a substituted aggregate** (`numeric(count(*))` is illegal; `count(*)` is fine). The fold is ADDITIVE; dropping the raw aggregates Splunk's eval would keep emits `eval_after_agg_drops_source` (a warning, never a silent drop). `median(x)*2` folds flat (a median is scalar *within one level*; only across a subquery boundary is it a keyed object).
  - **Fold-blockers keep the subquery** (the row-wise eval then runs on the OUTER over the exposed columns): a non-fold-safe function (`concat`, `numeric`, `lower`/`upper`/`substring`/`replace`/`split`, …) **or any reference to a facet key** (`refersFacetKey`). A facet-key reference blocks the flat fold *even when every function is fold-safe* — a flat `SELECT <event-field> … FACET <event-field>` is invalid NRQL ("FACET cannot be used when selecting on event fields"), and aggregate × event-field is rejected (both staging-verified).
  - **`where`-on-aggregate and trailing `stats` keep a subquery** (no `HAVING`; aggregates are rejected in `WHERE`). Stacked `where` layers AND-fold onto one outer `WHERE` (`stats|where`, `where|where`); a trailing `stats` re-aggregates over the exposed columns; both compose with the eval fold (`stats|eval|where|stats`).
  - **Non-scalar extraction via `getField`**: `median`/`percentile` expose keyed objects (`{50:v}`/`{N:v}`) across the boundary — a WHERE reference binds `WITH getField(col,'<N>') AS <name>` (collision-free name via `pickFreeName`), a trailing-aggregate arg inlines `getField(col,'<N>')` (median→`'50'`, `percN`→`'N'`; `extractNonScalar`). A scalar aggregate (`dc`→`uniqueCount`) filters directly, no `getField`. `uniques`/`values` (lists) have no scalar extraction. Any keyed-object/list reaching select/where/bindings/orderBy/facet OUTSIDE a `getField` wrapper → loud `eval_after_agg_nonscalar`.
  - **Guards — all loud `unsupported`, never silent-wrong**: `compound_collapse_unsupported` (a residual row-wise nested inner, or a reference to a column the inner no longer exposes); `compound_trailing_regroup_unsupported` (a trailing `stats … by <field>` whose facet keys ⊄ the inner facet keys — `_time`/`timestamp`/bin-alias exempt ONLY when the inner carries `timeseries`); `subquery_name_collision` (two inner aggregates resolving to one exposed name — `duplicateExposedName`; NRQL keeps the first, so a `getField` keyed off the last would read null). When a fold branch already pushed a specific message, the generic post-pass guard is suppressed (`foldPushedUnsupported`) so the chain stays loud with one clean diagnosis.
  - **head/tail between two aggregations** → deliberate `unsupported` (`head_between_aggregations`): SPL keeps the first N rows in stats order, a nested-subquery `LIMIT N` keeps the top N by aggregate value — different selections. `handleHead`/`handleTail` set `ir._headBetweenAgg` when post-aggregation; the next `handleStats` consumes it. A head/tail after a SINGLE stats is unaffected (valid `LIMIT N`).
- **WHERE as condition list**: `ir.where` is `IRNode[]`, not a single tree. Handlers `push()` conditions; emitter joins with AND. No null checks needed.
- **Field replacement scoping**: `applyFieldReplacements` only replaces in select/where/facet/orderBy — NOT in bindings/expand/dataSource. Prevents corrupting WITH/EXPAND source expressions.

## Expression Walking
- **Single expression walker**: `walkEvalExpr(node, ir)` (`evalHandlers.js`) is the only expression walker — one parameter, no resolver/strategy argument. It translates the typed `u_expr` ladder (`EvalArith`/`EvalBoolOp`/`EvalComparison`/`EvalNot`) in a switch. There is **no** `walkExpr`/`walkStatsExpr`/`resolveStatsFunc`/`resolveEvalFunc` (never built) — do not reference them.
- **Eval expression representation (SHIPPED)**: One unified typed ladder (`u_expr` and below in `spl.grammar`). All four call sites — eval func args, top-level eval assignment, stats function args, and stats `fn(eval(...))` inner — reference `u_expr` directly. The grammar produces typed `EvalArith`/`EvalBoolOp`/`EvalComparison`/`EvalNot` nodes; `walkEvalExpr` handles them in a switch. No flat-string round-trip; `buildArithmeticExpr` and `tryParseDotConcat` deleted. The `u_atom_stats_extra` rule handles stats wildcard tokens (`count(*)`, `app.*`) with a `![0-9]` guard to prevent `a*2` from being swallowed as a wildcard. **Known deferred (corpus demand confirmed):** infix `LIKE`, `IN`, and `if(cond,1,0)`→plain-predicate unwrap are not yet in the ladder — `LIKE`/`IN` inside `eval()` currently hard-error.
- **Stats vs eval is a HANDLER split, not a walker strategy**: `stats`/`timechart` aggregate functions are resolved by `mapFunction(name, args)` (`splExprUtils.js:120` — `avg`→`average`, `count`→`count(*)`, …), NOT by the expression walker. `walkEvalExpr` runs in stats context ONLY for the `count(eval(predicate))` boolean (`fn.evalFilter`). In **eval** context an aggregate-named call has no NRQL form — `eval x = avg(a)` emits `unsupported` (verified). The same SPL token thus resolves differently by which handler processes it, not via a walker parameter.

## WHERE Comparison RHS
- **RHS eval tier**: `where_comparison` parses its RHS at the `u_add` tier (not `u_expr`); widening to `u_expr` would let `where a > b AND c < d` greedily swallow the `AND`. The `u_add` alternative must precede the bare `where_value` fallback, which stays last (reversing it breaks arithmetic RHS like `a > b + 1`).
- **Relative time → SINCE/UNTIL**: `_time`/`timestamp` compared to `relative_time()`/`now()` emits `ir.since`/`ir.until`, never inline WHERE (NRQL rejects relative-time in WHERE) — and produces no `BinOp`.
- **Numeric coercion both sides**: ordering ops (`> < >= <=`) wrap BOTH the LHS field and a bare-field RHS in `numeric()`, not just the LHS.
- **Unsupported over wrong**: a comparison RHS using a not-yet-row-wise NRQL function (`jparse`/`convert`/`cidrAddress`/`toTimestamp`/`decode`/`encode`/`mapKeys`/`mapValues`/`lookup`/`blob`/…) emits `unsupported` rather than non-compiling NRQL. `LIKE`/`RLIKE`/`IN` keep a literal-only RHS on the `where_value` fallback.

## Dashboard Time Tokens
- **Drop, never passthrough**: Splunk `$…$` tokens in `earliest=`/`latest=` are caught before `parseSplTime` and dropped with a warning; a `TemplateVariable` named `earliest`/`latest` (or `*.earliest`/`*.latest`) is likewise dropped — never emit `SINCE {{…}}`. No `$…$` or `{{…}}` may reach a SINCE/UNTIL/TIMESERIES clause; those accept only concrete literals.
- **Mixed window → unsupported**: a mixed literal+token window escalates to `unsupported` and clears any partial since/until (no half-window leaks). `span=$tok$` parses as a `SpanToken` and emits `span_token_unsupported`, with no TIMESERIES.
- **Per-call scope**: time-token flags are scoped per `translateSearchExpr` call — a subsearch's flags never escalate the outer query's window.

## SPL Grammar Leniency
- **Separator leniency scope**: comma/space/empty-interchangeable list separators apply only to stats/top/fields/by/IN lists — never to rename pairs or eval comma-chained assignments. Quote-as-token-boundary leniency is search-context only (do not generalize to eval/where).
- **`bin`/`bucket` `as X`** is a field rename, not the `min()` function — grammar and IR must never conflate them.
- **`!` as NOT** in `where` is guarded to match only before `(` or whitespace, never before `=` — preserving `!=` as a comparison operator.
- **`top` percent subquery** must inherit the outer query's WHERE clause (else the denominator diverges). `sort`/`timechart` `limit=0` → `LIMIT MAX`; `limit=N` → `LIMIT N`.

## Packaging & Monorepo
- **`@newrelic/` scope**: both packages publish under it (`@newrelic/query-bridge`, `@newrelic/dashboard-importer`); each scoped package needs `publishConfig.access: public`. Root `package.json` stays `private: true` — the workspace root is never published.
- **Dependency direction**: `@newrelic/query-bridge` **defaults to zero runtime dependencies** — keep it dependency-free unless a dep buys correctness that is impractical to hand-roll reliably (e.g. a small, vetted RE2 oracle such as `re2js` to match `capture()` semantics — the translator is destined for the NR Logs UI, where a small MIT/0-dep lib is negligible). `re2js` is that exception and is its only runtime dep; the importer carries `fast-xml-parser` and `turndown`. The **one-way direction is firm** — importer → translator, never the reverse.
- **Repolinter hard gate (newrelic-experimental ruleset)**: the root `README.md` must open with the experimental `<picture>` banner within its first 5 lines AND contain a `../../security/policy` link; a root `LICENSE` must exist; a local `CODE_OF_CONDUCT.md` must NOT exist (centralized in `newrelic/.github`). These four are the only ERROR-level rules — `THIRD_PARTY_NOTICES` is WARNING-level. `THIRD_PARTY_NOTICES.md` lives at the repo root, regenerated by `npm run third-party:notices` (the OSPO `oss` CLI, run against an isolated tree because npm workspaces hoisting hides deps from it) and gated in CI by a regenerate-and-diff step. (Remaining publish runbook lives in Jira NR-578293.)
- **New bin scripts ship executable**: a script declared in a package's `bin` (`packages/*/bin/*.js`) MUST be committed mode `100755` (`git update-index --chmod=+x`). npm sets the exec bit on `bin` files at install, so a `100644` tracked mode leaves the workspace dirty after `npm ci` and fails CI's no-uncommitted-changes gate. Both `spl2nrql.js` and `spl-dashboard.js` are 755.

## Dashboard Importer
- **`DashboardModel` is the seam**: both parsers (Simple XML, Studio) produce it; all emitters (Terraform, NerdGraph, UI-paste) consume it; no stage downstream of the parsers branches on source format. The neutral `vizType` enum is the parser↔emitter contract — adding a viz type touches one map per side, never the pipeline.
- **`detectFormat` owns unwrapping**: returns `{format:'simple-xml'|'studio', payload}[]` — it expands the REST envelope (one unit per `entry`, skipping `content.isDashboard === false`, routing by `content.version`), strips Studio's `<definition>` CDATA (and passes pure-JSON Studio through), and decodes XML entities; downstream parsers each receive one clean single-format payload and never re-unwrap. CDATA-stripping happens for the envelope (`hint`) path too, not just standalone. Malformed JSON / missing core sections → loud throw.
- **`translateWidgets` is the single placeholder chokepoint**: a widget becomes a `markdown` placeholder (title + fenced original SPL + reason, same grid slot — layout preserved) when `Widget.unsupportedReason` is set (parser-flagged), the query is empty, the translator returns unsupported/errors, OR `vizType ∉ EMITTABLE_VIZ_TYPES`. Nothing is silently dropped or emitted wrong. A placeholder emits a `text`-only markdown widget, never an `nrql_query` block (the shapes are not interchangeable). Conversely, a `markdown` widget carrying `options.text` (a Studio image rendered `![](url)`, or a native `splunk.markdown` body) is emitted as a **clean** markdown widget (`markdownText`), not a placeholder — there is nothing to translate.
- **`EMITTABLE_VIZ_TYPES` is the single source of truth**: derived from the emitter's `WIDGET_BLOCK` and shared parser→translate→emit. The emitter THROWS if a non-emittable vizType reaches it — the chokepoint guarantees it can't, so a throw means a pipeline bug, never a silent degrade. `WIDGET_BLOCK` maps `area/bar/column→bar/pie` to real provider blocks; there is no `widget_column` or `widget_scatter` (column→bar; scatter/map/unknown → placeholder).
- **Dashboard tokens → `{{tok}}`, bare / value / quoted**: a `$tok$` becomes NRQL `{{tok}}` as a bare search term, an unquoted comparison RHS (`index=$env$` → `index = {{env}}`), OR a fully-quoted RHS (`index="$env$"` → `index = {{env}}` — the dominant corpus form, ~13.6k occurrences); no `numeric()` coercion in any case. The unquoted form is handled in the grammar `search_value` rule; the quoted-standalone form in the `splToIR` Comparison handler (a string RHS matching exactly `^\$name\$$`). Token-name charset allows `. : - _`. **Affixed tokens** (token inside a quoted value; handled in the `splToIR` Comparison handler right after the standalone check): NR substitutes `{{tok}}` in **value position only** — never inside a string literal/pattern (verified via `dashboardCreate` + NRQL execution, staging acct 1, 2026-06-22). So a **wildcard-only** wrap (`"*$tok$*"`, `"$tok$*"`, `"*$tok$"`) → `field LIKE {{tok}}` (the `irToNrql` `Like`/`NOT LIKE` cases pass a `{{`-prefixed pattern through unquoted, mirroring the Identifier `{{` passthrough) plus a `wildcard_token_like` warning — the `%` wildcards must live in the *variable's values*, which the importer can inject for a static enum but not for a free-text/search-backed value. A **literal affix** (`"*fps-$id$*"`, `"$id$-suffix"`) has no faithful translation → `affixed_token_unsupported` (loud placeholder, never silent-literal). Time tokens are the exception (dropped — see Dashboard Time Tokens).
- **Classify every panel viz child**: `parseSimpleXml` maps `chart/table/single` to real widgets and `event/map/html/viz/list` to placeholder-bound widgets (`unsupportedReason`); it never iterates a fixed tuple that lets unknown viz tags vanish. A widget's title is its viz `<title>`, falling back to the panel-level `<title>`.
- **Per-panel time folds into the base search**: a panel `<search>` with literal `<earliest>/<latest>` siblings is prepended as `earliest=… latest=…` so the translator emits SINCE/UNTIL; a `$tok$` bound rides the time-token drop (never leaks). A `<input type="time">` default is captured into `model.defaultTimeRange` — capture only, no NR dashboard-level time slot to emit into yet.
- **Variables**: `<fieldset>/<input>` → `model.variables` (dropdown/radio/multiselect → enum, text → string, time → `defaultTimeRange`, not a variable); the emitter renders `variable {}` blocks. `replacement_strategy` is per-variable — `number` iff every known value is numeric, else `string`. A single-FACET search-backed dropdown → `type="nrql"` (NR populates from the facet values); a multi-field or untranslatable source degrades to a static enum (if it has choices) or a free-text string — never an empty/invalid enum. A multiselect token's `= {{tok}}` comparisons are rewritten to `IN ({{tok}})` (NR expands a multi-var to a comma list). A `*` default/choice emits a co-located "means-all is literal in NRQL" comment. nrql variables use the plural `account_ids` list; widgets use the singular `account_id`.
- **Base search composition**: a document-wide `id→query` map resolves `<search base="id">` post-process panels. A non-transforming base (no `stats/timechart/chart/top/rare/dedup/eval`) composes as `base | post-process`; a transforming, missing, `ref=` saved-search, or chained base becomes a placeholder. `baseRef` is recorded either way.
- **Splunk defaults**: a `<chart>` with no `charting.chart` option defaults to `line` (Splunk's default), or such panels wrongly become placeholders.
- **Terraform output**: three files — `<slug>.tf` (dashboard), `versions.tf` (provider pin `~> 3`), `variables.tf` (account_id + sensitive `newrelic_api_key` + provider block) — and no `backend` block (that is the consumer's). `variables.tf` never contains a literal API key. The provider `region` is set by `--region` (default `US`; `EU`/`JP`/`Staging` accepted, validated+canonicalized at the CLI boundary — `Staging` routes the provider to `staging-api.newrelic.com`).
- **Deterministic + safe identifiers**: re-running on the same input produces byte-identical output so `terraform apply` reconciles cleanly. `slugify` prefixes digit-leading names (Terraform identifiers can't start with a digit); `--account` validates numeric and rejects non-numeric loudly.
- **HCL escaping**: emitted HCL must escape Terraform `${…}`/`%{…}` as `$${…}`/`%%{…}` and any Splunk `$token$` delimiters, or the `.tf` is syntactically invalid.

## Dashboard Studio (parseStudio)
- **`parseStudio(json)` → `DashboardModel`**: iterate `layout.structure[]` for widget order + px `{x,y,w,h}`; each item's viz is `visualizations[item.item]` (a missing one is skipped). Widget title = `viz.title` → `viz.options.title` → `''` (trimmed); doc title = `doc.title` → `doc.label`. CDATA is already stripped by `detectFormat`, so `parseStudio` only `JSON.parse`s.
- **`VIZ_MAP` (Studio `type` → neutral vizType)**: match the `visualizations.<id>.type` field exactly, never a substring. `splunk.table`/`events`→table; `splunk.singlevalue`/`singlevalueradial`/`markergauge`/`fillergauge`→billboard (gauge style lost); `splunk.markdown`→markdown; `splunk.line`/`column`/`bar`/`area`/`pie`/`scatter`→the matching neutral type; `splunk.choropleth.svg`→map (full dotted id). An unrecognized `splunk.*` → `vizType:'unknown'` + loud `unsupportedReason` (→ chokepoint placeholder). VIZ_MAP may emit `column`/`scatter`/`map`; the emitter (not the parser) collapses those per `EMITTABLE_VIZ_TYPES` (column→bar; scatter/map→placeholder).
- **Decorations & literal-content vizzes**: `splunk.rectangle`/`splunk.ellipse` (`DECORATION`) → dropped (no widget, never placeholdered). `splunk.image` → clean markdown `![](src)` **iff** `options.src` is `http(s)`, else dropped (no usable URL — not a broken widget). `splunk.markdown` with a non-empty `options.markdown` → clean markdown (body carried in `options.text`); an empty body falls through to the placeholder path.
- **Compose-and-delegate, with a narrow interim guard.** `parseStudio` composes Studio `ds.chain` SPL (`parent | fragment`) and hands it to the translator — it builds NO subquery-wrapping logic of its own (one-way importer→translator dependency). The lone exception is an **interim guard**: because master's translator still emits silently-wrong NRQL for `eval`/`head` after a transforming base (`stats|timechart|chart|top|rare|dedup`), `resolveDataSource` sets `unsupportedReason` (→ loud placeholder) for exactly that shape (`TRANSFORMING` base + `GUARDED_POST` = `eval|head` fragment). The guard is **temporary and dated**: once the translator's post-aggregation subquery-wrapping/fold work lands on master (in flight on `fix/subquery-wrapping`, #44), the guard is removed (a 2-file follow-up) and those chains upgrade from placeholders to real widgets. Do NOT broaden it into a blanket transforming-base placeholder — that is the rejected Simple-XML model; the sibling `2026-06-25-simplexml-base-delegate-design.md` proposes converging Simple XML onto this same delegate model (not yet built).
- **`resolveDataSource` (chain walk mechanics)**: `ds.search` → `options.query`. `ds.chain` → recurse `options.extend` to the root, propagate the parent's `unsupportedReason`, then compose `parent | fragment` (the fragment's leading `|` is stripped; an empty fragment yields the parent unchanged) — UNLESS the interim guard fires (transforming base + `eval`/`head` post-process → placeholder, above). A cycle (`seen`), a missing dsId, or a `ds.savedSearch`/`ds.csv` root (no inline SPL) → `unsupportedReason` → placeholder.
- **`pxToGrid` (lossy)**: Studio px → NR 12-col grid via `CANVAS_W` (`layout.options.width` or 1200) and `ROW_PX=100`; `x` clamped 0–11, `w` clamped 1..(12−x), `y`≥0, `h`≥1. Proportions preserved, exact pixel positions not. Normalization lives in the parser so the `DashboardModel` seam stays grid-only.
- **`parseInputs`**: `input.timerange` → `defaultTimeRange` (first time-input wins; only a comma pair like `"-24h@h,now"` → `{earliest,latest}`; a comma-less named preset is skipped — never split on a missing comma; a time input is never a variable). `input.text` → `string` variable. `input.dropdown`/`input.multiselect` → `enum` from `options.items`, else free-text `string` (search-backed Studio dropdowns deferred), `multi` set for multiselect. An unknown input type → no variable (absent, not silent-wrong).
- **`runImport` bulk + per-unit isolation**: returns one result per `detectFormat` unit (a REST envelope → many) — either a built dashboard `{slug,files}` or a skipped entry `{skipped:true, index, reason}`. Each unit runs in its own try/catch, so one malformed entry never aborts its siblings or emits a half-built dashboard; the CLI prints each skip to stderr, and an all-skipped/empty export is still success (exit 0). A malformed envelope itself still throws at `detectFormat` (a top-level loud error). Built-dashboard slugs are de-duplicated across the export (first wins the bare slug, then `-2`, `-3`); the CLI writes each under `out/<slug>/` when there is more than one dashboard, else flat in `out`.

## Emitter & Encoding
- **Smart backticking**: Only backtick identifiers with dots/dashes/spaces/colons/curlies. Simple names bare. Macros (`$name`) pass through.

## Messages & Pipeline
- **Message catalog**: All user-facing messages in `src/messages.js`. Handlers call `messages.key()` — no inline template literals. Lead each message with a meaningful word: `SPL_TO_NRQL.md`'s generator backticks the first token (a message starting "a transform…" renders as `` `a` transform… ``). `splExprUtils.js` uses lazy getters for `resolveStatsFunc` warnings so spies work. Message-key consistency is enforced in `test/spl/spl.test.js`: every `warningFunc`/`unsupportedFunc` array entry is validated against `messages` (an undefined key fails the case), and the spy check asserts the arrays are exhaustive (all fired messages listed).
- **Pipeline-level detection**: `splToIR.js` tracks state across the pipeline loop (dedup seen, mvexpand fields) and emits warnings after the loop (capture count, FACET LIMIT default, cascading/cross-field mvexpand). Individual handlers don't have pipeline context.

## Deferred Translation Targets
- **Native JSON access (deferred — keep `jparse()`-first)**: NRQL is gaining native JSON property access (`field['key']`, `field[0]['sku']`, `mapKeys(field)`) that would be cleaner and faster than `jparse()`. The translator deliberately does **not** emit it yet. It is gated on three things, not just a release date: (1) the feature reaching GA, (2) `FACET`/`EXPAND` working on native-typed values — without it our mvexpand path (`EXPAND jparse(...) + FACET string(...)`) can't use native access, and (3) forward auto-conversion of stringified JSON — most log JSON arrives producer-stringified and otherwise still needs `jparse()`. Also blocked by design: the translator has no account/schema context, so it can't know whether a given attribute is stored native — adding a native-emit path requires a caller-supplied per-attribute type hint. This corroborates the EXPAND-as-last-resort stance (EXPAND is Limited Preview — see CLAUDE.md and `docs/ARCHITECTURE.md`). Detailed status/triggers are tracked privately, out of tree (`docs/local/`, untracked).
